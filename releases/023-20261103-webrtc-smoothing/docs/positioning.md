# 项目定位与可验证的快速入门目标

修订：2026-10-11。状态：定位建议与设计目标，未实现、未计时验证。依据见[工作流调研](research/2026-10-11-workflow-positioning.md)。架构源仍为[architecture.md](architecture.md)。

## 1. 目标用户与价值主张

面向需要组合、切换不同机器人、遥操输入、相机和策略的实验室研究者，建设采集与推理运行基础设施。目标是减少反复集成和定位故障的成本，让同一实验流程可用于遥操采集、策略执行、人工纠正、回放和评测。

建议表述：**复用经过验证的设备组合，快速建立可观测、可接管、可复现的机器人实验链路，把更多时间用于策略与任务设计。**

当前不存在“经过验证的组合”，A1–A6均为待验收目标。候选优势必须由后续实验转化为事实。提供接口扩展能力与声明某个硬件受支持是两回事。

## 2. 项目边界

- 核心：设备能力和显式映射、配置预检、主机/依赖隔离、session、所有权与最终guard、原始记录/回放、策略资产/时序/运动适配、最小评测证据。
- 交接：向训练器导出有语义和谱系的数据；从训练器接收完整策略资产；向上层任务系统提供受约束执行和证据。
- 外部：机械/电气装配、专用标定算法、标注平台、分布式训练、奖励/世界模型研究、任务规划/记忆、自主恢复策略、高保真仿真建模。通过插件接入，不把它们全部纳入首版。
- GUI低优先级，复用同一后端；易用性首先靠验证过的profile、预检错误说明、指南和恢复流程。

复用按条件分层，不能只凭统一接口保证：

| 迁移 | 应争取的复用 | 必须重新核验 |
|---|---|---|
| 同实验台重启/换开发机 | session配置、任务脚本、数据/评测工具 | 设备身份、权限、依赖、健康、标定是否仍有效 |
| GELLO换Quest/手机 | 执行/记录/策略及报告 | 输入追踪、离合器、坐标映射、延迟与接管 |
| FR3换Piper | 应用流程和契约校验机制 | 自由度、工具/夹爪、模式、映射、动力学、策略兼容 |
| 改相机/物体/任务 | 记录、部署和诊断设施 | 标定、视场、预处理、评测分布；可能重采与微调 |
| 真机换仿真 | 配置结构、应用与接口测试 | 资产、观测真实性、时间、接触、复位；仍需真机验证 |

自定义遵循分层路径：已有profile参数 → 显式映射/观测处理插件 → 新设备/策略适配器。文档应告诉用户在哪一层扩展；新增插件必须通过契约/故障测试再进入参考组合。避免一个自定义应用重新承担所有驱动、安全和录像职责。

## 3. “跑通”的五个层次

1. **识别与只读**：目标设备身份、能力和观测健康正确，不产生运动。
2. **控制链**：授权的输入→映射→仲裁/guard→执行→反馈可追踪；按固定协议验证接管与停止。
3. **采集链**：产出通过QC的episode，日志可读、时间/语义明确、可回放。
4. **推理链**：兼容策略资产成功装载，满足输入/动作/时间预算，执行证据与模型请求对应。
5. **任务能力**：在固定评测协议下达到任务成功/效率指标。

端口连通、TCP连接或电机首次移动不足以证明第2层；控制链通过不足以证明第5层。软件停止入口也不替代现场硬件急停与控制准入。

## 4. 快速入门目标的计时合同

下表是候选验收目标，没有通过实验的承诺。物理测试只能在用户明确请求后进行；所有门槛检查均保留。

| 档位 | 明确前提 | 候选目标 | 结束条件 |
|---|---|---|---|
| Q0：无硬件体验 | 已准备开发主机、已安装锁定核心依赖、随包fake数据/配置 | ≤10分钟 | fake输入→执行反馈→至少10秒有效记录→回放检查；含所有权冲突/过期动作演示 |
| Q1：参考实验台复用 | 精确软硬件组合已验证、依赖已装、硬件已装配、标定有效、现场准入完成 | ≤10分钟 | 重新probe/预检，通过第2层并记录至少10秒有效episode |
| Q2：参考实验台首次软件配置 | 硬件已装配、OS/驱动满足profile，安装包可用；需要用户配置身份、映射和软件校准/准入 | ≤30分钟 | 完成配置和必要软件校准/准入检查，通过第2/3层；profile若达不到则不能列入此目标 |
| Q3：新增设备/未知组合 | 缺驱动、未知OS/固件/停止行为或需新映射 | 暂无分钟级目标 | 记录到首个通过契约/现场验收组合的工程时间、改动和障碍 |

计时开始于符合书面前提的用户开始教程，结束于报告生成。手工编辑、校准、重试、错误排查和等待全部计入该档位墙钟时间，另记录主动操作时间。首次安装、下载、装配、现场准入等前置成本单独测量并报告总准备时间；不能只展示预热后的漂亮数字。Q2涉及的软件校准及现场核验计入Q2；预先完成的电气/机械准入在准备成本中列出。

推理链另测：已准备可兼容策略、GPU及权重后，到完成资产检查、影子测试和授权执行报告的时间。不能用Q1的控制链数字代称模型下载、训练或推理任务成功。低延迟/RTC/IK等选项也必须满足相同链路和准入要求。

“各种机器人”应改为“已验证参考组合及可扩展设备接口”。支持条目必须含型号、工具/传感器、输入路径、OS、固件/SDK、控制模式、标定和测试证据。A1的GELLO、手机WebXR分别验收；A2与A4不能因均为Piper而共用一份兼容结论。

## 5. 闭环中薄而必要的实验契约

以下为字段设计，尚无schema或CLI。应附着在已有session/episode/artifact上，不新增必需的庞大服务。

| 拟议记录 | 最小字段/意义 |
|---|---|
| TaskSpec / EvalSpec | 任务/评测版本；物体/场景/初态与变化范围；成功、超时、中止与干预规则；复位协议；场景划分或种子（适用时） |
| DatasetManifest / QCReport | 原始episode引用及hash；导出/过滤/标注版本；角色/动作/时间语义；训练/评测划分；归一化统计来源；缺帧/对齐/动作拒绝等质量结果和阈值 |
| RunReport | 策略资产、图/plan、标定、OS/驱动实际版本；任务和初态；各次结果、用时、接管、stop、安全事件；复位时间；原始证据引用 |
| FailureTag / CollectionRequest | 人工或插件标注者/版本、置信或待诊断状态；设施/契约/时序/场景/策略等原因；需要重标定、修配置或定向补采什么 |

QC门槛为任务和profile声明的值，不硬编码全平台通用阈值。人工纠正同时保留策略原意图、实际控制者和实际发出的动作；不把混合控制episode默认当作纯专家示教。未知标签不得填成成功或奖励0。

训练交接检查observation/action语义和归一化/预处理一致性，返回PolicyArtifact引用数据版本与训练配置。自动任务判定必须注明判定方法与验证证据；首版可以人工判定，保留原始视频以便审计。RunReport区分自主成功、辅助成功、超时、故障/安全中止，报告完整分母。

## 6. 如何证明优势

先用fake及基础仿真验证接口，再以A1为第一真实参考组合。比较实验至少包含：新用户首次配置、熟悉用户重启/复用、换输入/相机、换设备主机/OS、换策略、故障诊断。之后A1→A2可检验异构组合迁移，不能仅展示同一台设备重复启动。

基线使用实验室当前最佳方案与适用的官方快捷路径，包括匹配硬件的LeRobot、DROID/厂商工具或现有ROS脚本。固定任务、硬件、功能和安全要求；如果没有同硬件基线则报告具体对照及局限，不宣称全面优于某个项目。

计时和可用性评测同时报告：

- 到第2/3/4层的墙钟时间与操作时间、前置准备时间、完整成功率、超时/失败及外部帮助次数。
- 配置/代码改动量、可复用模块数量、数据有效比例、诊断与恢复时间、支持profile维护成本。
- 端到端延迟/动作年龄与观测对齐质量；控制链效率和策略任务成功率分别报告。
- 人工复位时间和有效episode/小时，避免“启动很快但持续采集很慢”。

先做5–10名不同经验用户的形成性测试，记录所有尝试和问题以修正教程；小样本不支持稳定p95或广泛人群结论。报告n、中位数、范围及失败数；扩大样本后才讨论可靠尾部指标。采用配对/交叉顺序减少先后学习效应，固定预热状态并公开被排除的前置步骤。不得只保留成功用户或由作者代操作。

只有当明确组合在该协议下可独立复现，才对它发布分钟级目标与支持状态。若实验显示快速入门一般，而换配置/定位错误显著更快，应把定位落在已证明的收益上。
