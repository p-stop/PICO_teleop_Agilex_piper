# 真机数据质量、泛化与失败归因

2026-10-17；研究建议，不是实现或硬件验证报告。[任务 checkpoint](../../plans/2026-10-17-data-quality-research.md)。

## 核心判断

高质量数据是学习控制的重要条件，但真实任务表现同时取决于数据、可观测性、模型、控制器、推理时序及评测分布。失败不能自动归因于模型，也不能全部归因于数据。基础设施的价值在于让这些因素能够被独立测量和对照。

质量至少分为六层：记录完整、时间/几何/动作语义正确、任务信息可观测、示教行为合适、目标分布覆盖充分、训练部署一致。文件可读、帧率达标和轨迹平滑只覆盖其中一部分。

## 怎样理解仿真与真机差异

理想化仿真可使用准确状态、统一时钟和确定的动作生效时刻；真实系统必须面对曝光积分、遮挡、时钟偏差、缓冲、控制器迟滞和接触变化。仿真表现好可能说明策略解决了那个仿真分布，不能据此定位真机失败。仿真也可以主动加入观测延迟、丢帧和动力学变化，用来控制变量。

不要将真实变化全部称为坏数据：

- 错标签、时间倒退、单位错误、缺帧却伪装成新帧：记录缺陷，应修复并追踪受影响范围。
- 光照、物体材质、合理安装变化：部署分布的一部分，需要有效覆盖。
- 滑落后的重新抓取：可作为正确恢复示范；与滑落前失败动作分段标注。
- 夹爪闭合、接触冲击、必要等待：可能是任务关键事件，不能用速度/jerk/静止阈值一刀切删除。
- 目标持续不可见、执行器本身无法达到要求：属于观测/硬件/控制设计瓶颈，继续增加相同类型数据未必有效。

作为量级说明而非现场测量：物体或末端相对速度为0.2m/s，图像与动作错位100ms，对应约2cm位移。即使每路都显示30FPS，这种错配仍然可能存在。帧率、延迟、曝光时刻、跨设备同步和推理时的观测年龄必须分别报告。

## 当前代码能证明什么

[架构](../architecture.md)已经规定原始 MCAP、版本化训练出口、控制权及下发/反馈分离；§15明确任务评测、QC与失败归因。这些方向支持上述研究问题。

本轮静态读取的 [episode_qc.py](../../src/robot_infra/episode_qc.py)已有实收FPS、流缺失/时间间隔、时间倒退、profile失配、队列溢出、中断、文件完整性检查。对齐目前以 received_ns 最近邻生成，报告显式给出 exposure_synchronization_verified=false。因此通过该 QC 不能推导出曝光同步、动作标签正确或数据适合学习。工作区实现可能继续变化，后续应固定源码版本重新审查。

建议将报告拆为完整性、时序、几何/语义、视觉、行为、覆盖六类结果，保留 pass / fail / unknown 和证据引用。阈值按设备/任务profile确定。不能在没有测量时，把跨时钟域直接相减或自动优化相关性当作真实时钟校准。

## 最小可用的后续切片

建议先做一个离线 episode 审查器：选择一次尝试，同时播放三路视频，显示原始帧时间及未知时钟关系，并画出手柄意图、IK目标、网关后命令、发布receipt、反馈与夹爪事件。点击异常能追到原始消息、配置/模型/标定版本；每项结论能导出机器可读报告。

接着加入以下量化项，而不是先堆积模型和设备支持：

| 维度 | 建议记录/测量 | 不应作出的推断 |
|---|---|---|
| 时间 | 原始source、接收、可获得的曝光时刻、时钟映射/不确定度；p50/p95/p99间隔和观测年龄 | 接收时间接近不等于拍摄同步；常数延迟不能描述所有抖动 |
| 动作 | 人意图、映射/限速后目标、实际下发及反馈；明示训练action取哪一层 | 反馈不是命令；发布成功不是执行确认；跟踪误差不必然是标签错 |
| 几何 | joint顺序/单位、TCP、URDF、内外参、图像变换及其版本 | FK与同一模型输出一致不等于物理TCP已标定 |
| 图像 | 模糊/冻结/黑帧候选、目标/夹爪可见性、曝光/增益/白平衡（有则记）、捕获与预览分流 | 固定曝光不自动适合所有环境；简单清晰度分数不是任务信息量 |
| 行为 | 成功、失败、恢复、等待、接管和拒绝事件；保留人工审阅 | 成功episode中每一步不必然是专家动作 |
| 数据谱系 | 原始hash、过滤原因、重采样/裁剪版本、训练划分、归一化来源 | 导出能加载不等于标签语义正确；不能用测试集计算归一化 |

离线对称滤波可能使用未来帧；若将其用于模型观测，必须检查部署能否提供同样信息。相机的最近邻选帧也可能选到决策时刻尚未可用的帧。训练视图需要明确“当时可用”契约，而不只追求离线视觉同步。

## 区分模型、数据与部署的实验建议

以下是建议协议，尚未执行。设备动作需另获明确授权。

1. 固定一个短任务、成功判据、场景重置方法和可控评测变化。保存全部尝试，辅助成功、超时、系统故障分开统计；同时报告端到端完成率和条件化策略结果，避免选择性排除故障。
2. 先核查观测与动作链路，人工完成任务只能提供系统可用性证据，不能替代策略评测。若人使用额外视角或触觉，不能认为模型也拥有足够信息。
3. 固定模型和训练预算，对同一批原始episode生成不同版本训练视图：基线、仅修正时序/动作语义。另做等量子集比较以减少过滤后样本数量变化的混淆。只允许有证据支持的修正，记录参数及处理谱系。
4. 固定数据与权重，对比有依据的推理调度/延迟匹配。此步无需重训，用来识别执行层影响。
5. 固定总示范预算，对比同一场景重复采集和增加物体/位置/光照/日期覆盖；按完整episode和场景/物体/日期分组留出，不能随机拆相邻帧。
6. 在链路稳定后固定数据和部署比较模型、训练步数及随机种子。离线loss只是辅助指标，主要看闭环成功、失败类型、耗时、恢复及接管率。

首轮可以把每条件20–30次尝试作为排错试验预算，但它不是普适样本量或充分性证明。根据预期效应和方差再做样本量规划；随机/交错条件顺序，保留跨天重复，报告成功次数/总数及区间。多seed训练须分开报告，不能把同一模型的多次执行当成独立训练复现。

项目意义应以这些指标检验：发现数据问题的时间、无效采集比例、有效任务/场景覆盖成本、同模型在修复前后的闭环改善，以及可复现实验所需的人力。基础设施提供诊断和可比性；最终泛化收益仍需实验支持。
