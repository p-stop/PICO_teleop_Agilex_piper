# ADR-0004：实验运行闭环与有前提的快速入门目标

日期：2026-10-11。状态：设计决定；产品定位和时间数字为待验证建议。

## 背景

用户要求核验完整真机工作流、项目覆盖和分钟级控制链定位。现有架构已重点设计采集/推理/安全/回放，但任务评测和数据质量交接较薄。LeRobot/LeLab等已有完整入口，图形界面、插件和快速开始不能独立构成差异证据。

## 决定

- 聚焦异构实验台的采集与推理运行设施；复用训练/仿真/上层任务生态。首切片和A1–A6优先级不变。
- 将Task/EvalSpec、DatasetManifest/QCReport、RunReport与FailureTag作为已有session/资产的薄契约扩展；逐步实现，不在本轮新建训练或标注平台。
- 数据/动作/时间契约在采集前定义，并随数据导出与策略资产传递；训练评测划分和干预来源明确。
- 从原始日志和结果出发做失败归因，返回设施、契约、任务或定向采集，不默认所有失败都需要重训。
- 复用分别讨论接口/流程、配置/资产、数据语义、权重/任务能力；硬件和场景迁移均需重新验证相关层。
- 10分钟/半小时仅作为特定准备条件下的Q0–Q2候选验收目标；未知组合无固定时间承诺。前置成本、失败和人工帮助全部公开记录。
- 支持范围以独立可复现的型号/OS/驱动/输入/profile证据为准，不能用统一API或上游支持列表替代。

## 后果

项目价值更集中于反复集成、迁移、持续采集和故障诊断成本，首动演示之外可检验。需维护参考组合、操作指南、兼容矩阵和计时证据，可能比写通用接口更费工程时间。若研究者只用一个成熟标准组合，官方工作流可能更快，应如实报告。

详情见[定位协议](../positioning.md)和[工作流证据](../research/2026-10-11-workflow-positioning.md)。所有字段仍为草案，不产生新的已实现能力或硬件支持声明。
