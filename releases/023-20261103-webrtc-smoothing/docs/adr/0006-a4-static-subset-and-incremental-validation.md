# ADR-0006：A4静态子集优先与已有实验台渐进验证

日期：2026-10-16。状态：设计决定，待实施与现场验证。

## 背景与决定

用户新增高优先组合，并明确它是A4的子集：双Piper+夹爪、双D435腕部、固定D435/D435i/D455、PICO优先/Quest3备用、Ubuntu24.04。主机已可分别控制两臂为用户报告；PICO型号和固定相机仍待确认。用户要求先遥操数采、后策略推理。

- 场景ID用A4-S，不重编号A1–A6。近期推进A4-S→A1→A2，完整A4的底盘/头部固定相机及协调控制另验。
- 固定相机三个型号、PICO/Quest3、各OS/SDK/固件形成独立profile分支；抽象接口可共用，只有实际测试的分支标通过。
- 先冻结已工作的驱动/固件/主机环境，再审计接入。源码下载HEAD不等于安装版本；不为统一环境强制把A2升级到24.04或替换控制栈。
- 从环境盘点、独立VR/三相机/反馈，到多端点fake、明确模型/映射/最小sim或shadow，最后经现场安排做单臂/双臂物理与数采验收。完整A3不是等待项，但对应控制链的无硬件验证仍必要。
- M1固定fake协议不直接扩张成物理模式；下一切片先明确执行端身份、per-endpoint/group授权、实际时钟/后台停止、受限多源记录与设备backend。
- 设备本机唯一写入/最终guard及停止保护不能由Windows、SSH、浏览器或上游launch代替；初始化enable/TCP/夹爪写入需显式审计，非运动查询和passive读分开。
- 先实现遥操采集证据与QC，后续再接明确策略artifact/推理服务。保留原始MCAP与训练数据出口的分层。

## 后果

可复用现有Piper/QuestArm工程减少重复搭建，同时必须识别其dirty快照、旧ROS/Python、自动enable和IK参数。增加一个范围小的A4-S验收分支，不宣称已完成完整A4或硬件跨OS兼容。未知PICO型号可能改变输入适配路线，但不阻碍环境盘点和多端点fake实现。
