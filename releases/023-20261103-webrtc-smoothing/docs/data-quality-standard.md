# 数据质量量化标准草案

[研究依据](research/2026-10-22-data-quality-quantification.md) · [指标定义JSON](assets/data-quality/metrics-proposal.json) · [管线数学模型](research/2026-10-22-pipeline-mathematical-model.md)

**本文规定建议如何测量与解释数据质量，不是已经实现的QC接口，也不是采集操作命令。** 当前实际能力仍以 episode-qc/1、training-view/1 和[项目状态](project-status.md)为准。草案适用于不同机器人、传感器和动作空间；角色、维度、单位、期望流由profile声明，A4-S的14维动作只是一个具体实例。

## 1. 先明确用途，再判定质量

建议把质量检查组织为：

~~~text
只读原始数据 → reader解析事实 → metric测量与定位
                                   ↓
                    profile：用途、必需项、阈值、证据
                                   ↓
         人工/模型辅助阶段标注 → curator生成版本化训练视图
                                   ↓
             evaluator：固定训练和部署条件检验收益
~~~

reader不判断任务成功；metric不删除数据；profile不隐藏未知项；curator保留来源、时间轴和mask；evaluator不使用筛选时已经看过的测试集。学习型评分器和设备适配器都可以替换。

| 判定 | 含义 | 消费规则 |
|---|---|---|
| pass | 必要数据齐全，满足明确且适用的标准 | 只对该指标、用途、版本成立 |
| fail | 有充分证据违反该标准 | 排除受影响用途或片段；保留原始证据 |
| unknown | 缺字段、时域未知、样本不足或标注未完成 | 必需项未知则训练就绪状态为pending；诊断仍可用 |
| not_applicable | 当前用途明确不需要这项 | 不进入该项分母，给出原因 |

**monitor_only是评估模式，不是第五种合格结果。** 有测量但尚无可靠阈值时，不产生pass/fail；结果判定为unknown，原因是threshold_not_calibrated，仍展示测量值。没有测量时value=null，禁止用0表示未知。必需项有fail则该用途不准入，否则有unknown则pending，其余必需项均pass才准入；必需项不能被not_applicable跳过。

例如：未采深度的episode可以进入RGB-only候选集；要求三路深度的训练用途则判定缺流，不能靠补零通过。成功标签未知的工程测试可以用于性能诊断，但不能自动成为成功BC示范。

## 2. 每个测量至少携带什么

| 字段组 | 必需信息 |
|---|---|
| 定位 | episode/source hash、流/关节/相机角色、起止时间、时钟域、阶段 |
| 定义 | metric ID与版本、单位、计算法、估计器/滤波参数 |
| 样本 | numerator/denominator及其单位、有效样本/时长、未知覆盖率 |
| 结果 | value或统计量、异常区间、pass/fail/unknown/not_applicable |
| 阈值 | 操作符、值、用途、依据类型、依据链接、校准日期与版本 |
| 证据 | 事件ID、媒体帧引用、标定/人工标注/模型评分的来源 |
| 不确定性 | 时间误差界或置信区间及覆盖假设；不可测原因 |

“p95为30ms”没有说明是按事件还是按时间加权、receive还是exposure时刻，就不是完整指标。缺失区间必须展示，不能只统计好样本。

## 3. 指标字典

以下ID与JSON一致。**现状**的“部分”表示现有文件可支撑部分计算，并不表示新的指标报告已经实现。阈值除明确文件/接口契约外都需按任务校准。

### 3.1 记录可信性与时序

| ID / 指标 | 定义、单位与分母 | 数据/现状 | 判定方式 |
|---|---|---|---|
| I01 文件与引用完整性 | 损坏/缺失引用数；分母为manifest/index列出的全部对象，另查未索引对象 | deep检查已有；不能发现所有从未写入的对象 | 必需对象损坏/缺失数=0；hash证明一致性，不证明内容真实 |
| I02 必需流与有效覆盖 | 必需流缺失数；各流有效覆盖时长/episode窗口时长 | 流存在、计数已有；边界与有效时长需补 | profile声明必需角色；覆盖容差按任务 |
| T01 采样间隔与边界缺口 | 同流相邻间隔p50/p95/max，首帧前、末帧后缺口，单位s；乱序数单列 | 内部gap/FPS已有，边界需补 | 期望频率与最大可容忍中断分别定义；平均FPS不替代max gap |
| T02 因果观测年龄 | 按时间加权年龄分位数、超龄时长/总窗时长、unknown时长/总窗时长 | 可算接收年龄；曝光年龄需时钟映射 | 必须区分receive-age和source-age；未知映射不认证曝光年龄 |
| T03 多模态同步误差界 | 各配对源时刻差+映射误差界；单位s，报告配对覆盖 | 现有nearest receive不提供曝光证据 | 时域可比后按任务误差预算；未标定unknown |
| T04 输入—命令链完整与延迟 | 每阶段匹配数/应匹配数、重复/拒绝/遗漏数，延迟分布s | 原始输入/命令/guard/receipt已有；全链ID及源端账本不完整 | 先限定“应执行”的状态/ownership；拒绝不能一律算丢包 |

令采集窗为$[t_0,t_1]$，源时刻映射为$\widehat s$。已知可观测集合为$K$，年龄$A(t)=t-\widehat s_{\nu(t)}$。同时输出：

$$
C_K=|K|/(t_1-t_0),\quad
P_{\rm stale}=\frac{|\{t\in K:A(t)>A_{\max}\}|}{t_1-t_0},\quad
P_{\rm unknown}=1-C_K.
$$

分位数明确是在$K$内计算，不能把未知时间当低年龄。时间加权实现可对分段线性age精确积分，或用声明分辨率的固定网格近似；不能仅对到达帧求均值。长间隔、暂停和epoch切换不外推成有效覆盖。

需要严格区分两个统计：**source-age**是信息在物理世界中的旧程度；**receive-age**是主机距收到最新信息多久。网络/驱动积压可能让receive-age很小而source-age很大。

没有源帧序号、复位语义和计划帧数时，不能从间隔精确还原真实丢帧率。可报“超期间隔率”或“相对期望帧数的缺额估计”，名称注明估计；启停曝光、丢弃与实际传感器FPS必须区分。

### 3.2 动作语义与执行

| ID / 指标 | 定义、单位与分母 | 数据/现状 | 判定方式 |
|---|---|---|---|
| S01 动作/观测契约 | 单位、joint order、绝对/增量、base/TCP、左右/相机角色、夹爪方向的必需字段不一致数 | 部分显式；末端frame仍有未标定字段 | 必需契约明确匹配或经过已审查转换；不靠数值“看起来相似” |
| S02 动作标签可追溯性 | 已知目标分量数/全部应有分量数；全维有效行数/全部候选行数 | training-view已有null/mask与发布来源 | 不把反馈充当未知目标；硬件执行ACK未知需保留 |
| S03 末端/FK一致性 | 同时同frame的平移误差m、旋转测地角rad | 原生Euler/转换四元数已有，frame/时间需确认 | 未满足前提unknown；同FK来源仅自洽，外部标定另测 |
| E01 目标—反馈跟踪 | 各关节时间加权RMSE rad、绝对误差p95/max、覆盖率；夹爪m独立 | 日志可做部分离线计算 | 按速度、接触、执行模式校准；保留未补偿值与最佳lag诊断 |

S02中当前A4-S行是左6关节+左夹爪+右6关节+右夹爪。通用实现应从manifest枚举维度。训练的state使用实际状态；action使用所选层的明确命令。若使用IK前意图或网关前目标，应另建有名有版本的视图，不混称为最终执行动作。

夹爪目标0mm但反馈32mm可以表示夹住物体，不能按“目标不匹配”自动丢弃。应检查的是：触发意图是否按当前规则转成目标、目标是否发布、是否有阻挡/接触、传感器是否可信。持续目标在无新边沿时仍有效，不人为要求每个采样点都出现新指令。

姿态误差可用$e_R=\arccos(\operatorname{clip}((\operatorname{tr}(R_1^TR_2)-1)/2,-1,1))$。四元数$q$与$-q$代表同一旋转，不能用逐分量差当角误差。

### 3.3 视觉与深度

| ID / 指标 | 定义、单位与分母 | 数据/现状 | 判定方式 |
|---|---|---|---|
| V01 可解码与冻结候选 | 解码失败帧/索引帧；source ID重复、像素重复及最长持续s分别输出 | deep媒体解码检查已有；联合冻结检测拟新增 | 必需帧可读为契约；静止内容不直接判冻结 |
| V02 任务区域可见性 | 已标注关键物体/接触ROI可见时长/应可见阶段时长；最长遮挡s | 需阶段与ROI人工/模型标注 | 按任务声明至少哪一路可见；评分器需人审校准 |
| V03 模糊、曝光、压缩 | ROI锐度代理、饱和像素比、估计运动模糊px；按相机/阶段统计 | RGB可算代理；曝光/增益未必记录 | 默认monitor_only；跨分辨率/纹理不共用锐度阈值 |
| V04 深度有效性 | ROI中valid深度像素/ROI总像素；工作距离内比例；标靶残差m | 流可选，旧new_test无深度 | 未要求深度N/A；要求则检查缺流、scale、invalid编码、RGB-depth映射 |

V01的deep verification不表示已采集depth图。V04的valid像素规则由传感器定义：不能把所有非零整数都视为正确距离；反光、遮挡、超量程应单独诊断。

V02还应报告操作者预览年龄与机器人记录流年龄的差别：模型能看到清晰画面，不代表示教者当时看到了及时画面。预览延迟会改变示范中的纠正行为；未记录预览端显示时间时只能标未知。

### 3.4 行为、覆盖与部署

| ID / 指标 | 定义、单位与分母 | 数据/现状 | 判定方式 |
|---|---|---|---|
| B01 任务/子任务结果 | success/failure/unknown、完成度rubric、标注者/依据；成功数/全部已执行尝试另报未知数 | new_test结果待标注 | 未知不自动成功；任务描述与标注版本必需 |
| B02 阶段效率与恢复 | 操作/必要等待/无意停顿/恢复时长及占比；重试、接管次数 | 需阶段标注，session状态只覆盖一部分 | 恢复与等待不按低速度/高jerk自动删除 |
| C01 目标部署覆盖 | 目标加权覆盖率、每单元计数、均衡度有效组数 | 需场景/物体/操作者等metadata与目标计划 | 先定目标单元和最低样本；数量不等于独立性 |
| C02 近重复与划分泄漏 | 跨train/validation/test同源episode/衍生组数；近重复候选比 | 精确来源可追踪，近重复需算法 | 已知同源跨集合=0；近重复模型候选需复核 |
| D01 训练—部署契约匹配 | 必需字段不匹配数及显式adapter版本 | 训练与workflow配置部分已有 | action空间/dt/归一化/视觉变换/历史/cache等逐项审计 |
| D02 推理执行时序 | 推理/传输/队列延迟s、deadline miss数/全部请求、欠载时长/执行时长、接缝与实际跟踪 | fake执行已有，真模型端到端未验证 | 按模型action dt和控制需求校准；单看平均推理速度不够 |

对成功率，必须同时报告已执行N、成功S、失败F、未知U，满足N=S+F+U；S/N是“确认成功占全部尝试比例”，不是把未知断言为失败。S/(S+F)仅为有标签子集的条件化成功率，可能有选择偏差。正式试验应消除未知；系统故障作为端到端未成功尝试计入分母，单列原因。

不建议对B02直接设置“jerk越小越好”。运动质量要在同任务、同阶段、同控制模式内比较；接触、迅速闭合夹爪、纠错和合法多解需要不同解释。离散三阶差分对采样噪声敏感，任何jerk统计必须给出单位、重采样dt和滤波版本。

## 4. 如何制定阈值

采用四种明确来源：

1. **contract**：如文件可读、单位一致、必需字段存在。这是用途契约，不由某篇论文成功率推导。
2. **task_error_budget**：任务空间误差预算推导时序/标定容差，必须给出速度上界、误差分配与假设。
3. **empirical_validation**：本项目健康/故障数据、人审及独立闭环实验支持；记录适用任务和验证集。
4. **literature_reference_only**：外部论文的具体阈值，保留上下文，仅供比较，不作为本机准入条件。

教学例：给平移时序项分配5mm误差，速度上界0.1m/s，时钟误差界5ms，则年龄预算为：

$$A_{\max}=0.005/0.1-0.005=0.045\ {\rm s}.$$

若速度升至0.5m/s，预算仅5ms。这不是新配置默认值。该预算没有分配视觉定位、标定、跟踪等误差，不能宣称总误差小于5mm；近似模型需考虑任务旋转、接触和加速度。预算为负说明假设不相容，不能截成0后当作已满足。

当前本地示例的**历史工程基线**如下，既不是机器人今日配置，也不是文献公认的高质量阈值：

| 路径 | 值 | 含义 |
|---|---:|---|
| teleop-session.example.json → recording.qc.min_fps_ratio | 0.8 | 30FPS目标对应24FPS最低比例 |
| 同文件 → recording.qc.max_frame_gap_s | 0.15s | 已有内部帧间隔限制 |
| 同文件 → recording.alignment.max_delta_s | 0.05s | 主机接收时刻最近邻容差 |
| 同文件 → recording.qc.max_unaligned_ratio | 0.1 | 已有对齐无效行比例 |
| training-a4s-rgb.example.json → sampling.max_state_age_s / max_image_age_s | 各0.1s | 因果接收时间视图的最大年龄 |
| 同文件 → sampling.action_offset_steps | 1 | 在观测时刻t+1/30s取持续有效的已发布目标，需连同30FPS理解 |

**建议先把unknown与异常位置做完整，再调严阈值。** 否则只会得到更多“QC不通过”，却不知道是源时钟、网络、存储、动作模式还是任务本身的原因。

## 5. 如何实施和验收下一切片

第一阶段建议离线实现I02/T01/T02/S02，复用当前reader及媒体索引：先输出可测事实，再暴露无法计算source-age等原因。T04新增关联ID/源端时序需要独立的记录协议变更，不能给旧数据回填不存在的证据。

拟议验证样本应覆盖：完整合成流、仅首尾缺帧、平均FPS正常但局部停顿、源时钟未知、未来最近邻、夹爪接触导致目标/反馈不等、缺初始目标、重复帧、正常静止、无深度与必需深度、合法恢复、跨集合衍生重复。先fake/offline，再明确授权后的真实采集。

人工抽审需包含随机样本和异常候选。若只审异常候选，只能估计该候选集precision，不能估计全数据recall。模型/VLM评分必须记录版本及人审混淆矩阵，且不要让模型看到最终测试结果后再调阈值。

训练收益验证比较全量、随机等量子集、规则筛选子集；锁定模型、任务、训练计算预算、部署与测试划分。另以固定采集人时比较重复采集与覆盖补全。报告成功/完成量、接管、时长和系统故障；保留学习seed和场景聚类。小样本只用于排错与效应估计。

当前研究交付不宣称这些插件已经实现，也不改变任何既有episode状态、记录文件或运行参数。
